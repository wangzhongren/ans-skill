01 / 能帮你什么

接手、修改和排查，都有依据。

适合需要持续维护、经常换对话或由多个 AI 接力的项目。

  1. 01

    下一轮，少从头解释

    功能说明和工作记录，让下一轮 AI 知道项目现在怎么运行、还有什么没做。

  2. 02

    只想改一处，先定范围

    先确认方案和改动范围，再按角色的文件边界修改。

  3. 03

    多个 AI 做事，知道找谁

    开发、测试、验收各有负责角色，出问题知道该找谁处理。

  4. 04

    过阵子再改，能查原因

    从功能说明回看设计和修复历史，知道当初为什么这样做。

02 / 一次协作

用一个草稿，说明角色怎样配合。

假设用户要保存尚未提交的工单。工单角色处理输入和保存流程，存储角色负责读写；各自维护自己的文件。以下只是协作示意，ANS 不是一个已经交付的工单应用。

Owner 01

工单角色

对保存过程负责：检查输入，组织步骤，处理业务结果。

  1. 接收输入
  2. 组织保存
  3. 检查规则
Owner 02

存储角色

对持久化负责：通过公开约定读写记录，返回实际结果。

  1. 接收记录
  2. 读写存储
  3. 返回结果

公开约定连接两个角色

工单 → 记录与保存请求；存储 → 成功结果或错误
Model：由指定所有者维护数据定义，供各层共享。修改共享约定后，重新核对受影响的调用者。
03 / 责任与代码

一个角色，可以跨多个代码层。

角色回答“谁对结果负责”；分层回答“代码怎样配合”。不是一层一个角色，也不要求每个功能在五层各建一个文件。

  1. Interface接收外部输入，返回结果
  2. Pipeline组织步骤与分支
  3. Service处理业务规则
  4. Provider访问文件、数据库或外部资源
  5. Model共享的数据定义与约束

职责清楚，交接才有着落。

五个管理角色开箱即用：沟通是客户唯一接口，先确认意图理解再交策划；策划说明用户目标、架构设计和共有契约；统筹在方案确认后按统一标准判断团队（不变、改边界、拆分、新增或合并）、排定角色指派并安排每个角色的工作流；独立验收按同一版策划方案判断是否完成；人事只按客户确认后的团队计划建立或修改角色卡和文件边界——统筹定要什么能力和边界，人事补充能力描述并落成角色卡。项目管理只在统筹判断需要技术架构工作角色时按需建立。

  • 上下文始终绑定一个角色，不在同一对话中来回换身份。
  • 客户窗口只加载沟通角色；策划、人事、统筹、验收由沟通启动独立子代理；工作角色只通过统筹调度。
  • 跨角色阅读不会自动带来修改权限。
  • 测试通过与最终验收是两件事。

04 / 开始工作

三道客户确认闸门，再安排实际工作。

五个管理角色开箱即用。沟通先确认意图理解，方案完成后确认方案，统筹按统一标准判断团队（不变、改边界、拆分、新增或合并）并排出团队计划后，再确认角色指派；三道闸门各自确认自己的对象和版本，只有客户明确同意才能通过。客户未同意，人事不写卡、不派发开发；默认勾选、团队共识、方案已写完和沉默都不算同意。配置、边界和本次任务一起限制可写文件，预检不会自动替你扩权。

  1. 01

    意图确认（闸门 0）

    沟通接单，写清目标、范围、优先级、非目标、已授权边界和已知约束；客户确认理解正确后，才交策划。

  2. 02

    方案确认（闸门 1）

    策划写产品方案、架构设计和可验收标准；沟通交客户确认方案，未确认不进入团队规划或人事写卡。

  3. 03

    角色指派确认（闸门 2）

    统筹给出哪些角色、谁做、各自范围和写集；沟通交客户确认，未同意人事不写卡、不派发开发。

  4. 04

    人事、预检、开始

    客户同意后，人事按计划写卡；调度准备配置并运行只读预检，再逐角色授权和预留。

07 / 常见问题

开始前，可能还想知道。

读文档，需要启动服务吗？

不需要。Markdown 和网页正文可直接阅读。运行权限预检与任务工具需要 Python 3.10+；业务项目可以使用其他语言。

角色看懂了别人的代码，就能顺手修吗？

不能。读取是为了理解；写入仍受角色边界、项目配置和本次任务限制。跨角色问题交调度安排，由对应所有者修改。

有一个测试通过，就算整个任务完成吗？

不算。开发者负责自身检查，固定测试角色运行联调与回归；独立验收依据当前版本和原始证据判断通过、返工或证据不足。

在哪里查看五层和功能流程？

从 README 进入五层说明和角色卡。策划给出产品方案和架构设计；如按计划建立项目管理角色，它维护实现层架构。各角色用功能导航链接当前功能说明、流程图和历史记录。

脚本被禁用，或者页面暂时打不开怎么办？

禁用 JavaScript 仍能阅读全部正文、打开链接并手动复制命令。页面暂时打不开时，可直接访问公开仓库 README、论文和许可证；页面不提供离线缓存或自动切换。

# 让已有项目的文档进入云端历史

项目原有的 `dev_docs` 和 `bug_docs` 没有被原同步器收集，手动同步成功也不代表这些方案已上传。本次改为让项目明确指定文档目录，继续使用原来的文件位置；上传后能按原路径查询以前的版本。代码和本地测试已经完成，安装与部署状态见文末。

## 为什么会漏

1. 原[本地收集函数](../../dashboard/versioned_sync.py)只扫描项目根目录下的 `角色卡/`、`role-cards/`、`doc/`、`docs/`。本项目的两个目录在 `kefuAgent/src/platform/docs/`，不在原扫描入口内。
2. 原收集函数还按固定目录名筛选，`dev_docs`、`bug_docs` 不在名单里。因此只换一个扫描入口也不够。
3. 原[云端历史查询](../../dashboard/versioned_sync.py)只查询路径含 `design` 的 Markdown。即使文件被上传，原 `--design-list`、`--design-path` 也查不到这两个目录的历史。现在另有通用历史入口。

2026-09-28 只读核查：当前项目收集 30 份文档。两个遗漏目录另有 228 份 Markdown，加入后共 258 份，原文约 2.2 MB；单个文件均未超过现有 256 KiB 限制。本次数量低于现有 300 份、原文合计 4 MiB 的上限，但后续增长仍须明确报错，不能悄悄漏传。

## 本地怎样指定目录

在业务项目根目录已有的 `.ans-dashboard.local.json` 增加可选字段 `documentRoots`。本次代码已支持该字段；下方只列新增字段，保留原有的项目 ID、服务器地址和 Key：

```json
{
  "documentRoots": [
    "kefuAgent/src/platform/docs/dev_docs",
    "kefuAgent/src/platform/docs/bug_docs"
  ]
}
```

原有默认目录继续收集。额外目录递归收集 Markdown，按项目相对路径保存，不能用文件名代替完整路径。同一路径只收集一次，不把 `dev_docs` 中的所有文件猜成“设计”，也不要求旧文档先改名、移动或补日期才能上传。

配置必须是项目内的相对目录。拒绝绝对路径、`..`、指向项目外的路径和符号链接；指定目录不存在时报错，不能把配置写错当成“没有文档”。额外目录只收集 `.md`，不把同目录的源码、附件或配置文件一起上传。配置工具更新 Key 时保留 `documentRoots`；安全查看配置时可显示目录，但继续隐藏 Key。

收集超过现有数量或大小限制时，列出明确原因并停止，不悄悄少传。是否需要分页或增量文档同步，后续有实际需要再定，不在这次提前增加。

## 从保存到查历史，完整流程怎样走

1. AI 把方案保存到项目原有的文档目录。
2. 用户执行原有的手动同步命令。程序读取默认目录和 `documentRoots`，把文档原文放进 `artifacts`，键为项目相对路径。目录配置错误或文件超限时，提示具体路径并停止。
3. 本地文件内容有变化时，先在本地同步 SQLite 记一版，再按原有流程拉取和上传。没有变化时不重复上传；云端与本地冲突时继续提示客户处理，不直接覆盖。
4. 云端将文档原文跟项目版本一起保存。网络失败时保留原有重试和待上传状态；本地保存成功不代表上传成功。
5. AI 通过新的通用文档历史查询，按原路径列出版本或取回指定版本内容。保留现有 `design-docs` 接口兼容旧客户端；新入口可查询所有已上传 Markdown，不依赖目录叫不叫 `design`。

新增查询使用 `document-history` 入口，CLI 对应 `--document-list`、`--document-path` 和 `--document-revision`。文件没上传时返回“云端没有这份文档”。同一文档内容没变化，不增加文档变更条目；首次接入只能上传本地现在有的内容，不能补造接入前已经丢失的旧版本。通用文档列表不沿用旧设计接口的前 200 份截断，避免本项目文档再次漏查。

新历史入口需要更新云端后端。现有后端的项目版本接口已经能存储合法相对路径的文档，因此本地收集适配和历史查询适配是两个步骤；不能把“已上传”与“新接口已可用”混为一谈。

这次适配不移动业务项目文档，不改业务源码，不自动开启定时同步。页面展示和角色 `features/` 导航不在本次范围内。

## 怎样确认修好了

2026-09-28 全部 129 项测试通过。新增回归覆盖：原有配置和默认目录仍可用；两个嵌套目录的文档能被收集；同名不同路径不覆盖；修改后可取旧版和新版；源码、Key、项目外文件和符号链接不会被收集；错误目录和超限都有明确提示；通用历史接口继续按项目 Key 隔离；旧设计历史接口仍可用。测试使用临时项目和本机 HTTP 服务，没有访问生产服务。

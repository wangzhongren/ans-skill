# 行动判断与沟通优化

1. **问题与目标**：将“主动但不过度”等笼统表述转成可分别判断的条件；用户反馈需要说明白、少啰嗦、多项内容优先编号。
2. **具体变化**：新增 [行动策略](../../references/action-policy.md)，区分硬边界、判断证据、可调行为和结果评价。行动顺序为检查授权、补足证据、选择最小有效行动、安排反馈。授权不是可被任务价值或置信度抵消的分数，熟悉用户也不自动扩大权限。
3. **流程衔接**：[工作流程](../../references/workflow.md) 复用已有授权，技术不确定优先检查或测试；缺少用户意图才提问。高风险有授权且证据充分时可采用分阶段执行。原有冻结、架构与验证约束继续适用。
4. **表达规则**：[主文件](../../SKILL.md) 要求先说结果、用具体语言，多项内容优先列 1、2、3、4，不凑项、不隐瞒失败或限制；[交付报告](../../references/evidence.md) 合并相关信息并链接证据。

涉及目录仅新增 `references/action-policy.md` 和本记录，其余为上述规则文件的小范围修改。业务代码、查询器、查看器与 JSON 格式不变。

验证：执行 skill-creator `quick_validate.py`、主文件/参考文件/本记录的链接及围栏检查、`git diff --check`。另检查六种决策场景：已授权低风险直接做；技术未知先查；较高风险分阶段；缺少意图再问；未授权先准备；不可逆且仍有关键未知则暂停该影响。未新增行为评分或强制解释模板，也未重复运行业务工具测试。本次验证不构成真实任务效果的量化结论。

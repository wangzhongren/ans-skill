# 架构设计: 实体管理

## 设计目标

实体管理角色负责游戏引擎中的实体与组件系统，提供以下核心能力：

1. **实体生命周期管理**: 创建和销毁游戏实体
2. **组件管理**: 为实体添加、移除、查询组件
3. **事件通知**: 实体和组件变更时通知其他系统
4. **高效查询**: 按组件类型组合条件查询实体

## 设计决策

### 决策 1: 实体即 ID + 组件集合

**方案**: 实体不作为"厚"对象，而是轻量标识符 + 组件容器。

**理由**: ECS 模式的核心思想是将数据（组件）与行为（系统）分离。实体只是一个聚合组件的容器，所有数据都存储在组件中。这种设计使得：
- 系统可以按组件类型高效遍历实体
- 组件数据布局友好
- 实体创建成本极低

**后果**: 外部系统（场景、渲染）通过实体 ID 引用实体，通过实体服务接口操作组件。

### 决策 2: 双层 Map 存储结构

**方案**: `Map<EntityId, Map<string, Component>>`

**理由**: 
- 通过实体 ID 和组件类型双重索引，O(1) 级别访问
- 与 TypeScript 的 `Map` 类型天然兼容
- 相比数组存储，删除和查找更高效

### 决策 3: 发布-订阅事件系统

**方案**: 实体服务内置事件系统，支持按事件类型注册监听器。

**理由**: 
- 解耦实体管理与其他系统（渲染、逻辑等）
- 支持并行角色开发，事件机制是跨角色通信的核心桥梁
- 监听器异常隔离，不会阻塞其他监听器

## 数据流

```
SceneManager                    RenderSystem
    │                               │
    │ createEntity()                │ queryEntities({ allOf: ['Transform', 'Sprite'] })
    │ addComponent()                │
    ▼                               ▼
┌─────────────────────────────────────────┐
│            EntityService                │
│                                         │
│  on('entity:created')                   │
│  on('component:added')                  │
│  on('entity:destroyed')                 │
│                                         │
│  ┌─────────────────────────────────┐   │
│  │       ComponentContainer       │   │
│  │  EntityId -> { components }    │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

## 与其他角色的关系

| 角色 | 关系 |
| --- | --- |
| 场景管理 | 通过 EntityService 管理场景中的实体 |
| 渲染 | 通过 queryEntities 按组件类型筛选渲染对象 |
| 主循环 | 通过事件监听感知实体变化 |
| 装配 | 创建 EntityService 实例并注入到引擎 |

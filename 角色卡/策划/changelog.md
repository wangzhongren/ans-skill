# 策划角色变更记录

- 2026-10-19：依据用户新增策划角色请求及主任务明确的责任划分新建角色。职责为用户目标、需求和完整产品流程方案；项目管理负责技术架构/实现设计与评审，统筹调度、开发、测试和验收各守自己的职责。只授予本角色导航、memo 与限定 `docs/design/` 目录权限；不创建本轮重复方案。Doc: [role-card.md](role-card.md)、[boundary.md](boundary.md)、[boundary.yaml](boundary.yaml)。

## 2026-10-22 — 五内置管理角色模型下的策划职责

按用户确认的五内置管理角色模型，策划职责扩展为产品方案、架构设计、共有业务契约和可核对完成标准；策划方案（产品方案＋架构设计）是独立验收的基线。项目管理改为按统筹团队计划建立的技术架构工作角色，只在已确认架构下做实现设计、技术契约和技术评审，不再默认拥有架构设计。同步更新角色卡与边界双格式中 `docs/design/` 的用途说明；路径不变，不新增角色或程序权限。Doc: [role-card.md](role-card.md)、[boundary.md](boundary.md)、[boundary.yaml](boundary.yaml)。

## 2026-10-22 — 返工裁决：本仓库策划路径与内置角色卡落地

依据 2026-10-22 返工计划及协调方转达的治理冲突，由 ANS 团队组建（招募，现人事）在角色定义与边界中明确：

- **写盘路径**：内置策划默认写 `docs/planning/`；本仓库以已接受的 Section 1 覆盖为 `角色卡/策划/docs/design/`，不并存第二套路径。现有产品方案、架构设计与共有契约继续留在 `角色卡/策划/docs/design/`，不迁移、不复制；如未来迁移，须先经治理更新本边界、角色卡和本记录。
- **角色卡与 memo**：内置策划在普通项目中不需要项目角色卡，也不建 `memo.md`；本仓库通过已接受的治理边界为内置策划保留项目角色卡、边界、`memo.md` 与功能导航，属于本仓库自用的项目本地落地，不改变技能默认，也不要求其他项目照做。通用依据见 `references/team-formation.md` 与 `references/planning-role.md`。

Doc: [role-card.md](role-card.md)、[boundary.md](boundary.md)、[boundary.yaml](boundary.yaml)。

## 2026-10-22 — 三道客户闸门中的策划职责

依据用户新增的流程要求，在角色定义中明确三道客户闸门：意图确认（闸门 0，沟通 → 客户）、方案确认（闸门 1，策划方案＋架构＋可验收标准 → 沟通 → 客户）和角色指派确认（闸门 2，统筹团队计划 → 沟通 → 客户）。策划只在闸门 0 后形成正式方案；方案完成后先交沟通取得闸门 1 确认，未确认前不进入团队规划或招募（现人事）；客户确认的版本是可追溯的验收基线。方案实质变更重开闸门 1，意图或范围实质变化由沟通重开闸门 0。同步更新角色卡开篇与执行原则；不改变角色身份、边界或程序权限。Doc: [role-card.md](role-card.md)、[planning-role.md](../../references/planning-role.md)、[communication-role.md](../../references/communication-role.md)。

## 2026-10-22 — 内置角色工作备忘录

依据用户新增要求，明确内置角色也维护自己的工作备忘录：策划默认路径为 `docs/planning/memo.md`，项目可通过已接受的治理边界覆盖到角色既有范围。memo 是角色私有的续接线索和已核事实，不是任务状态、不是角色定义、不写其他角色文档；它位于既有默认窄范围内，不扩大写权；策划完成工作后更新自己的 memo，属于交付的一部分。角色卡与边界路径不变。Doc: [planning-role.md](../../references/planning-role.md)、[role-card.md](role-card.md)。

## 2026-10-22 — 运行架构与上下文隔离

客户窗口只加载沟通角色；策划由沟通启动独立子代理上下文，只接收自己的角色、边界、授权、任务输入和交付要求，不在同一上下文切换为其他角色。工作角色只经统筹调度，策划不直接给工作角色派活、授权或启动。角色卡执行原则同步本条；不改变角色身份、边界或程序权限。Doc: [role-card.md](role-card.md)、[planning-role.md](../../references/planning-role.md)。

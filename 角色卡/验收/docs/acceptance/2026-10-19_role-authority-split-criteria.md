# 角色职责拆分：实施前验收标准

版本：2；修订日期：2026-10-19；作者：固定独立【验收】上下文。状态：标准已修订，尚无实施验收结论。

客户要的是：新需求由统筹直接安排各角色，项目管理做架构，开发和固定测试分别给出实际证据，由独立验收判断成果；安排工作的人不能用调度凭证自行验收。客户已授意修改，并明确去掉组长、由单独的内置 ANS团队组建 负责招聘和边界调整。

依据为[已确认方案](../../../项目管理/docs/design/2026-10-19_design_role-authority-split.md)、[项目法案](../../../项目管理/docs/project-rules.md)和[本角色边界](../../boundary.md)。下面提炼方案 A1–A12，不增加选装项。方案、标准或范围有实质改变时先交原所有者处理，不能在终验时降低标准。

v1（2026-10-19）绑定的方案 SHA-256 为 `2bb0ab2859f0b33ff27d7d58f5025ef950ed4d7fe265d69280d89220fec1ff6c`。用户随后明确“顺便在增加一个策划角色吧，负责策划方案”，原项目管理在方案第 11 节追加后续职责路由；本次实读新 SHA-256 为 `dc6cadf91ebfd84294288171e78194ad93fcf7dbb83e46118dcd2d88b64815d4`。据此显式升为 v2，仅修订 C8 与来源说明；C1–C7 不变，不新增代码条件，不改写此前方案归属，也不要求策划补造本轮重复方案。[实际策划角色与边界](../../../策划/role-card.md)已建立；其规范指南、导航和 memo 以各原所有者后续实际交付为准。

## 完成条件

| 标准 | 用户应得到的结果与必须证明的边界 | 方案覆盖 |
| --- | --- | --- |
| C1 凭证真正分开 | v2 初始化只固定经审核配置中的验收角色、边界和独立秘密摘要；缺配置、同秘密或请求覆盖身份均拒绝，初始化不生成或返回验收秘密。只有独立验收凭证能 accept-plan/verify；scheduler、worker、项目 Key、伪造 roleId/scope 均不能冒充，验收凭证不能 dispatch/revise。没有 mint/reset/降级入口，旧 coordinatorToken 不是新权限别名。记录无明文、status 对新旧及历史认证摘要脱敏。实际验收秘密由调度之外的可信操作端保管交付，身份名称、摘要和 AI 自述不能充当客户认证。 | A1、A2、A9 |
| C2 实施前确认可派发计划 | 未有当前 accept-plan 就不能 dispatch。预检绑定实际需求、设计、标准、角色定义、计划图及全部必需节点，包括跨角色独立测试节点，并保留可追溯的客户确认来源。需求、设计或依赖改变会使预检过期；删依赖或声称“不受影响”不能绕过新预检。 | A3、A8 |
| C3 三种结论有真实效果 | 真实 CLI 走通“开发检查→报告→阶段 pass→固定测试检查→最终 pass”；执行者 complete 只到 awaiting-verification。pass 在全部门禁满足后才 verified 并释放预约；needs-work 记录差异、进入 blocked 且保留预约，stop 后以 retryReason 开新批次；missing-evidence 记录缺项、保持 awaiting-verification 和预约，允许原范围补证。两种未通过结论都不放行下游。stop 只释放写预约，不能完成任务；调度不能直接 close，最终完成只由全部必需节点的当前有效 pass 派生。 | A4、A5 |
| C4 验收只接受当前真实证据 | 检查由批准配置的 argv 实际执行，认证 assignment 决定生产角色/worker/节点/批次，并记录环境、候选、时间、退出码和日志摘要。缺产物、失败/超时、日志丢失/篡改、检查改候选、完成后候选变化、标准/角色/配置变化或陈旧 stateRevision 都不能通过。验收引用逐项标准、实际产物、完成报告和检查；开发单测或外部成功日志不能冒充独立测试，原失败历史不能消失。 | A6、A7 |
| C5 祖先失效不会被下游掩盖 | verify、依赖派发和当前完成使用一致的有效性判断，覆盖 writeSet/readSet 与直接及传递依赖。即使直接依赖候选未变，祖先日志缺失或验收过期仍阻止下游并使当前完成为 false，保留历史结论。需求/设计修订传递失效；不受影响的理由由新 accept-plan 复核。脚本、fixture、相关输入或环境改变及换机器缺日志均按实际影响失效；不新增墙钟 TTL。 | A6、A8、A10 |
| C6 旧任务保留，新任务不被旧工具写回 | 新工具能按原 v1 渲染校验读取正常 Markdown/旧 JSON，但拒绝所有旧任务写入，不原地升级、不追认旧 verified、不因只读自动释放旧执行者。v2 真正删除 coordinatorTokenHash 与 assignment 的 tokenHash（含历史），不留别名。用基线 `6a7d4fe` 的真正旧 task_ops.py/coordination_store.py 对 v2 实测 dispatch、verify、ack、run-check、report、stop 均无法写入；报告列取得基线的命令及摘要，不能以新程序模拟代替。 | A9 |

## 终验需要的交付与证据

- 任务工具交付实际程序差异、当前功能/变更说明及 `scripts/tests/test_task_ops.py` 开发单测原结果；技能规范与项目管理交付各自范围内的当前说明；治理交付实际角色和一致的 MD/YAML 边界。
- 固定测试在隔离项目以真实子进程 CLI 运行 `scripts/tests/test_role_authority_flow.py` 的流程，并给出 `python3 -m unittest discover -s scripts/tests -v`、隔离 timer 回放及 Dashboard 回归/独立启动的原报告，逐项对应 A1–A12，写出失败、跳过和覆盖限制。timer 回放不代表浏览器启动或 TypeScript 编译已覆盖。
- 每份原报告须能定位最终受测候选、命令、环境、输入、规则/标准版本、真实退出码及日志。最终候选摘要覆盖相关产品/治理/测试输入，排除本验收结果和统筹后续说明，避免报告摘要自循环；相关输入再变更时重取受影响证据。
- 本验收只引用并核对上述原始证据，不代跑完整 QA。终验结果写入自己的 result 文档，逐条给出 C1–C8 判断、证据、缺项与责任所有者；工具接口只有在另有真实任务及授权时才提交。

## 判断口径与本阶段边界

全部完成条件满足且证据对应最终候选，才可判“通过”；有实际违反标准的结果判“返工”，交具体所有者；必要执行缺失、证据过期或无法定位候选判“证据不足”，交原生产者补证。两种未通过情况均不记完成。文档中写“计划测试”或单测成功均不能替代固定测试证据。

本阶段只修订标准，无实质需求歧义待客户再确认；尚未开展终验，开发和固定测试结果留待最终候选与原报告齐备后核对。未启用真实项目任务记录，不生成或转交真实验收秘密。测试可在隔离项目使用自有临时凭证，不能当作本仓库真实任务凭证。环境据统筹交接为 Python 3.14.7、支持 TS strip 的 `/usr/local/bin/node` v24.14.0，终验以原报告实测为准；缺 PyYAML 时不得声称 quick_validate.py 成功，替代检查及其限制须如实记录。

本次无选装；不新增服务、数据库、组模型、TTL、云端角色 Key 或旧任务自动升级，不包含发布/安装。通过有限测试不证明同 OS 操作者无法改配置，也不认证客户身份或自动发现隐藏依赖。

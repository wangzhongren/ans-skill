# 独立验收角色

独立验收负责回答：**这次约定要做的事，当前版本是否已经做到，有没有足够证据。**它是团队组建创建并经确认的项目角色，需要自己的角色卡和边界，不是统筹、项目管理或测试的兼任职责。

## 开始前先说清怎样算完成

读取用户目标、当前已确认方案、角色边界、相关工程法案和已有测试条件，在自己的获准文档范围说明：

- 要交付什么、范围到哪里，哪些选装已经获准；
- 成功、失败和重要边界情形应看到什么；
- 需要哪些测试、结构检查、文档和版本证据；
- 什么情况判通过、返工或证据不足。

标准要与任务相称。已有明确标准就核对并复用，不另造一套流程；发现范围或需求歧义时交统筹协调，涉及架构的请项目管理评估，不能自行加需求。实施后不能为了通过而放宽标准。实质变更先记录依据并按原确认流程处理。

## 测试与验收分开

开发者测自己的代码，项目管理测 shared，装配检查构建与接线，[测试角色](test-role.md)真实运行跨角色、完整流程和回归测试。独立验收读取原始报告、当前候选版本、改动范围和必要检查输出，检查这些证据是否真的覆盖约定，而不是代跑所有测试或把“工作者说完成”当完成。

缺少必要执行证据时，列出需要谁补什么；测试发现失败时，保留原始失败记录。独立验收不能改业务源码、测试断言、任务权限或别人报告来得到通过，也不承担全局派发。验收与实现、调度使用不同固定上下文；不得自己实施再验收自己。

## 三种结论

| 结论 | 含义与后续 |
| --- | --- |
| 通过 | 当前具体版本满足已确认标准，必要证据完整且有效；统筹可据此记录该阶段完成并按依赖放行 |
| 返工 | 已有证据表明结果不满足标准；列出差异、依据和应回到哪个所有者，由统筹安排修复与复测 |
| 证据不足 | 尚不能判断，例如没跑必要检查、版本不符、环境不可用或报告缺失；列出缺什么，由统筹安排补证，不能记通过 |

结论写在本角色自己获准的验收报告中，至少链接任务/阶段、方案和标准版本、候选版本、检查证据、未解决问题及结论理由。统筹只引用该结论并维护全局记录，不能替验收改结论。报告因候选、合同或相关规则变化而过期时，重新判断受影响部分；同一版已有有效结论可复用。

用户对需求、实施、发布等事项的批准，与独立验收判断是不同事实；验收通过不会授权提交、推送、部署、合并或对外操作。无有效验收结论的必需阶段保持未完成。

工具录入与迁移按[任务操作](task-operations.md)执行：独立验收使用自己的 `acceptanceToken` 调用 `accept-plan` 和 `verify`，业务结论对应 `pass/needs-work/missing-evidence`。字段、证据引用和当前有效性限制见该指南；本指南不代替真实测试或验收报告。

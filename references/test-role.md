# 固定测试角色

每个项目由 ANS 团队组建 创建并维护一份固定测试角色卡和边界，交用户确认。它是项目角色，不是新的内置角色，也不要求一直运行一个 Agent。已有专门测试角色定义就复用；测试执行上下文始终绑定测试角色。没有子代理时，在独立上下文里按授权顺序承接测试；无法创建独立上下文就报告待办，不在原上下文切换角色。

测试角色卡填写[角色卡模板](role-card.md#group-field-and-flat-roles)中的分类字段 `group` / `组别`，保持平级并直接向统筹交反馈。组别不能扩大测试范围或授予其他角色测试产物的写权。角色卡开头采用[长期维护者的工作立场](role-card.md#working-stance-for-every-role)：理解真实用户要完成什么，以及项目以后会怎样继续变化。以实际使用效果判断交付，帮助团队看清问题和影响，让后续修改有可靠的依据。

## 负责什么

测试前，读取本角色的 `memo.md` 和项目管理角色维护的 `docs/project-rules.md` 相关条目，确认规则状态及检查方法。缺失或未确认的规则要如实报告。测试报告可以引用规则和证据，但不能据此建立或修改全局约束。

1. **跨角色联调。**检查角色之间的数据、接口、错误处理和调用顺序是否符合已确认的设计。
2. **完整流程测试。**从真实入口检查用户能否完成操作，覆盖实际存在的判断分支、成功结果和失败处理。
3. **回归测试。**共享组件或功能修改后，检查受影响的原有功能，复测已修复的问题。
4. **给出明确结论。**记录测了什么、实际结果、对应版本、没测什么和仍存在的问题。测试通过只说明这些场景通过，不代替客户的业务确认。

## 与其他角色的分工

| 角色 | 测试责任 |
| --- | --- |
| 开发角色 | 编写并运行自己负责代码的单元测试和必要的层内契约测试；每层完成时先验证 |
| 项目管理角色 | 编写并运行 `common/shared/` 的对应测试，提供架构建议 |
| 统筹角色 | 安排测试、修复和补证顺序，记录当前阶段 |
| 独立验收角色 | 定义完成标准，根据当前证据判通过、返工或证据不足 |
| 装配角色 | 配置构建和测试运行环境，完成接线与启动冒烟测试 |
| 固定测试角色 | 独立检查跨角色接口、完整功能流程和受影响功能的回归结果 |

不能因为有固定测试角色，就把开发阶段的测试全部推到最后。测试角色可以提前根据已确认的设计准备用例；依赖尚未实现时，不能把替身测试写成联调通过。

## 文件边界与必读资料

团队组建角色在测试角色的 Section 1 中授予专属测试目录，例如 `test/<测试角色ID>/`，包含联调、完整流程、回归用例及相应的测试夹具和测试辅助代码。沿用项目现有测试位置和语言规则；需要共置的测试列明具体文件。另授予角色的功能导航、测试方案、问题记录和测试报告的实际路径，沿用已有 `docs/`，不创建架构 JSON。

测试角色可读取本次任务相关的源码、功能文档、已确认方案、共享组件清单和其他角色的测试结果。开始前加载自己的角色卡、边界、自己的 `memo.md`、项目管理角色 `docs/project-rules.md` 的相关已确认条目、[测试要求](testing.md)、[文档规则](documentation.md)及当前任务涉及的层约束。新增或修改测试代码同样遵守先交方案、确认后实施的要求；已确认的同版任务方案可以同时包含测试范围，不重复索要同一授权。

不能修改业务源码、`common/shared/`、其他角色的私有框架或单元测试，也不能修改构建配置、角色卡或权限来让测试通过。需要调整运行环境时，交统筹安排装配角色处理。测试辅助代码不能被生产代码引用。

## 从真实测试到独立验收

1. 统筹交付已确认方案、独立验收标准、功能范围、当前候选版本和相关角色，安排测试阶段；每个角色直接经过统筹授权和预留。
2. 测试角色真实运行授权范围内的检查，保留命令、环境、输入、候选版本和原始结果，区分通过、失败、无法运行和未测试。静态阅读或工作者自报不能写成运行成功。
3. 发现问题向统筹报告复现步骤、预期与实际差别、影响和版本。实现错误交所属角色修；架构缺口交项目管理评估，需求或方案变化先按既有确认流程处理。
4. 统筹安排修复后，测试角色对新候选复测受影响场景，保留旧失败及新结果。其他角色不得修改或隐藏测试报告。
5. 独立验收依据已确认标准和当前证据，判通过、返工或证据不足；统筹据此记录和安排后续。测试角色提供事实，不代替完成判断，也不修生产代码。

测试角色是项目里的固定职责定义，不代表一直开着一个 Agent。具体角色和边界由团队组建创建并获确认；已有测试归属不能因新增角色默默迁走。参见[独立验收](acceptance-role.md)、[统筹](scheduler.md)、[证据](evidence.md)。

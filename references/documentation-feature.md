# 新增功能文档：让人知道怎么用

写给第一次使用这个功能的人，也写给之后接手的开发者。读完后，他应该能回答**功能解决什么事、从哪里开始、输入什么、会得到什么**。

重点写：

1. **一句话说明用途。**谁会用、用来完成什么，不用“新增某某能力”代替实际用途。
2. **一个可照做的例子。**页面功能写操作步骤；CLI/API 功能写最短命令或请求，并给出必要输入和预期结果。
3. **成功与失败。**成功后用户看到什么、哪些数据被保存；失败时有什么提示、能否重试。重要限制直接写在相关步骤旁边。
4. **从哪里继续看。**给主要入口、相关设计或接口文档的链接；末尾用一两句说明做过什么验证，详细测试记录留在任务报告。

这不是代码改动清单。若用户只关心怎么使用，不应先读完十个文件名才能找到答案。字段表仅在字段本身是使用门槛时列出；完整契约链接到接口说明。

例如：“客服打开工单，填写未处理字段后点‘保存退出’。页面提示‘草稿已保存’才会关闭；失败时停留在原页面，已输入内容不丢失。”这比“完成工单草稿模块开发”有用。

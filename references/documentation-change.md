# 修改功能文档：说清前后差别

写给已经熟悉旧行为、需要适应新行为的人。读完后，他应该知道**以前怎样、现在怎样、为什么改、自己要不要调整**。

重点写：

1. **用一个触发场景比较前后。**例如“以前启动同步器后每 10 秒上传；现在只有用户运行同步命令才上传”。比抽象地说“优化同步策略”清楚。
2. **用短句划清范围。**旧行为在哪种情况下不合适？这次只改什么？哪些流程、数据和用法不改？不要把三件事塞在一个长句里。
3. **指出需要跟着改的地方。**旧命令、接口、配置或数据是否还能用；如果需要迁移，给出准确步骤。没有迁移就不要硬写一节。
4. **说明确认方式。**指出最重要的回归场景和结果；详细日志、候选哈希等留在任务记录或链接的测试报告。

不要重写整份功能说明。已有稳定用法继续链接原文档；这里只讲改变的部分。若改动还没部署，要明确“代码已改，线上尚未更新”。
